# Налаштування спільного журналу через інтернет

Застосунок підтримує спільні записи через Supabase. Для запуску потрібні власний проєкт Supabase і HTTPS-хостинг для статичних файлів.

## 1. Створіть базу даних

1. Створіть проєкт у Supabase.
2. У **SQL Editor** відкрийте файл `supabase-schema.sql`, вставте його в редактор і виконайте.
3. У налаштуваннях **Authentication** вимкніть самостійну реєстрацію. Створюйте або запрошуйте користувачів самостійно, щоб сторонні не могли зареєструватися й побачити спільний журнал.

Усі користувачі, яким ви створите облікові записи, бачитимуть і зможуть змінювати спільні записи.

## 2. Підключіть застосунок

1. У налаштуваннях API проєкту скопіюйте Project URL та **publishable key** (або legacy `anon` key).
2. Відкрийте `supabase-config.js` і вставте значення у `url` та `key`.
3. Ніколи не вставляйте `service_role` або secret key у браузерний застосунок.

## 3. Опублікуйте файли

Опублікуйте `index.html`, `supabase-config.js` і папку `assets/` на статичному HTTPS-хостингу, наприклад GitHub Pages, Netlify або Cloudflare Pages. Файл, відкритий через `file://`, не є спільним вебсайтом. У налаштуваннях Supabase Auth задайте URL опублікованого сайту як Site URL.

Після цього користувачі відкривають одну вебадресу та входять під створеними для них обліковими записами. Записи завантажуються зі спільної бази та оновлюються на інших пристроях приблизно раз на 10 секунд.

Експорт формує книгу XLSX з окремими аркушами для НРК і VAMPIRE. Під час першого експорту браузер завантажує бібліотеку ExcelJS із jsDelivr, тому для цього потрібне підключення до інтернету.

## Важливо про старі записи

Записи, які вже збереглися в браузері, залишаються там. Цей прототип не переносить їх у спільну базу автоматично. Перед переходом експортуйте звіт XLSX; за потреби старі записи можна повторно внести після підключення.
